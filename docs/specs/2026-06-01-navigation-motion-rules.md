# Super JSON Editor 导航与动效规则

## 目标

本文档定义 `super-json-editor` 的导航与动效语义。

它要解决的问题不是“让所有切页都动起来”，而是：

- 动效要表达用户意图
- 只有真正发生角色变化的页面才应该运动
- 不相关的页面应尽量保持静止

## 先区分两种布局模式

### `stack-flow`

这是默认模式。

特点：

- 当前可见区域只强调当前工作页
- 虽然内部仍有完整导航栈，但视觉上更接近“整页随导航流动”
- 不要求始终保留左侧上下文页

### `pinned-root`

这是固定 root 模式。

特点：

- 左侧 root 页固定
- 右侧为当前工作页
- 动效规则主要围绕“右侧页如何进入、替换、返回”展开

下面的详细动效规则，主要针对 **`pinned-root`** 模式。
`stack-flow` 更强调简洁和直接，不强求复杂上下文动效。

## `pinned-root` 的心智模型

编辑器内部维护完整导航栈，但视觉上最多强调最近两页：

- 左页：上下文页
- 右页：当前工作页

不是每次导航都会改变这两个角色，因此不能只用一种通用动画。

## 动效类型

### 1. `push`

当当前右页继续打开更深的子页时使用。

视觉含义：

- 老左页离场
- 老右页左移，成为新的上下文页
- 新右页从右侧进入

### 2. `replace`

当左页保持不变，但右页被另一页替换时使用。

视觉含义：

- 左页保持完全静止
- 老右页离场
- 新右页进入

### 3. `cut`

当动效会误导用户时，直接切换，不强行动画。

这通常出现在返回、跨层跳转、或上下文收缩时。

## `pinned-root` 导航规则

### 规则 A：单页进入双页

当当前只有 root 可见，且从 root 打开一个子页：

- 使用 `push`

原因：

- root 成为上下文页
- 新子页成为工作页

### 规则 B：右页继续深入

当左右两页都可见，且当前右页继续打开更深层子页：

- 使用 `push`

原因：

- 当前右页被提升为新的左侧上下文
- 新右页被创建

### 规则 C：左页切换右页

当用户从左页点击另一个子项，只替换右页：

- 使用 `replace`

原因：

- 左页上下文不变
- 只有右页变化

### 规则 D：root 保持，右侧切换另一个顶层入口

当左页仍然是 root，右侧切到另一个顶层项：

- 使用 `replace`

原因：

- root 仍是稳定上下文
- 右侧工作页变化

### 规则 E：从双页退回单页

当从“左页 + 右页”退回到只剩 root：

- 使用 `cut`

原因：

- 这是上下文收缩，不应该误导成“右页滑出”

### 规则 F：从双页退回另一组双页

当返回后，旧左页变成新右页：

- 优先 `cut`

原因：

- 这本质上仍然是可见历史收缩
- 直接切比误导性位移动画更可信

### 规则 G：跳转且左页不变

如果 breadcrumb 或其他 jump 保持左页不变，但更换右页：

- 使用 `replace`

### 规则 H：大跨度跳转

如果 jump 不保留清晰的 `push / replace` 关系：

- 直接 `cut`

例如：

- 从深层状态直接跳回 root
- 跳到一个与当前可见角色关系不明确的远处页面

## `stack-flow` 的约束

`stack-flow` 不追求把所有内部历史都可视化出来。

它的规则更简单：

- 默认展示当前工作页
- 返回优先使用直接的 `Back`
- 如无明显收益，不额外制造“上下文页必须出现”的动画

换句话说：

- `stack-flow` 优先保证清晰和轻量
- `pinned-root` 才强调左/右角色分化

## 产品约束

动效系统应始终优先：

- **不用误导性动画**

而不是：

- **为了动画覆盖率而强行运动**

在 `super-json-editor` 里，可信的交互语义比“动画很多”更重要。
