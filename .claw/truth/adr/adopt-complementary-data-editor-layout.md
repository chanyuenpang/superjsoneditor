# ADR: 以互补方式采用 `data-editor` 的高密度编辑布局

## 背景

`super-json-editor` 当前以 `src/editor/EditorShell.tsx` 的 stack/pinned 双页模型承载深层 JSON 对象和引用导航；`src/styles.css` 已有 52px 工具栏、固定表格布局和独立的展示型 demo 外壳。`vendor/data-editor` 则证明了另一组适合数组与行编辑的稳定模式：结构化工具栏、独立筛选轨、紧凑表格，以及覆盖展开且可调宽的右侧详情轨道。

这些模式解决的是高密度数组扫描和行详情查看，不等同于深层对象导航。外部参考事实及其版本绑定由 [`../data-editor-interaction-patterns.md`](../data-editor-interaction-patterns.md) 维护。

## 决策

- 保留现有 stack/pinned 页面作为深层 JSON 对象与引用导航的主模型，不用固定三栏布局替换它。
- 对数组和行编辑补充紧凑数据表与可调宽右侧详情轨道；详情以覆盖方式展开，保持表格尺寸和行上下文稳定。
- 将工作区工具栏稳定划分为“上下文与搜索 / 弹性空间 / 状态、视图与操作”，并把数组筛选放入独立、可横向滚动的筛选轨。
- 通过编辑模式语义 token 分阶段引入更紧凑的表面、边框、阴影、密度和选择反馈；展示页可以继续使用渐变、大圆角和较重阴影，但这些装饰不进入高密度编辑区的默认视觉层级。
- 引入顺序以 token 和结构分区为基础，再接入筛选轨和右侧详情轨道，避免用零散组件样式维持一致性。

这是一项采用方向，不表示上述补充能力已经在 `super-json-editor` 中完成实现。

## 备选方案

### 用固定三栏骨架替换 stack/pinned 导航

不采用。三栏骨架适合集合、表格和单行详情，但会削弱现有深层对象与跨引用逐级导航的上下文表达。

### 保持现有展示型视觉，不引入编辑模式 token

不采用。渐变、大圆角和重阴影适合 demo 外壳，却会放大高密度编辑区的装饰层级，并使工具栏、筛选、表格和详情轨道难以共享稳定密度。

### 在主表格内展开行详情

不采用。行内展开会改变表格高度和扫描位置；右侧覆盖轨道能在查看详情时保持表格结构和行上下文。

## 影响

- 深层对象导航与数组行编辑获得各自适配的空间模型，二者互补而不竞争同一入口。
- 右侧详情轨道需要明确宽度持久化、覆盖层级、关闭行为和小屏降级规则。
- 独立筛选轨需要与后续高级筛选共享同一筛选模型，避免形成两套状态来源。
- 编辑模式 token 成为后续布局迁移的前置依赖；新增密集编辑组件应优先复用语义 token，而不是复制展示页样式。
- 当前实现事实仍由 Truth 与源码锚点维护；当 `vendor/data-editor` 子模块提交变化时，应先重新检查版本绑定，再调整本决策所引用的模式依据。
